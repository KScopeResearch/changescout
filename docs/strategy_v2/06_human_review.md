# 06_human_review.md — AIと人間の役割分担

## 大方針

**「AIが全部やる」サービスではない。「AIでドラフトを作り、人間が価値を高める」サービスである。**

完全自動化されたAI SDRは、コストの低さと引き換えに「事実誤認のまま送信してしまう」
「文脈を外した提案をしてしまう」リスクを抱える。人間のレビューが入らないことによる
コストの非対称性（1通の誤送信が招くブランド毀損・信頼失墜は、削減できた作業時間を
容易に上回る）を踏まえ、初期フェーズでは意図的に人間の関与を残す。

一般的なHuman-in-the-loop型AI営業の考え方でも、AIは「調査・優先順位付け・ドラフト作成・推奨」までを
担い、人間が「対象アカウント・接触理由・メッセージの角度・コンプライアンス適合・送信可否」を
承認するという役割分担が推奨されている。誤ったメール1通のコストは「悪い返信」だけでなく、
ブランド毀損・到達率悪化・営業チームへの不信にまで及ぶとされる。

## 適用範囲の原則（例外を作らない）

Human in the Loopは「初期フェーズの暫定措置」ではなく、**入力チャネルを問わず適用される原則**である。
将来、Webフォームからの自己申告（会社ドメイン入力等）によるセルフサーブ生成のような
即時性の高いチャネルを検討する場合でも、生成結果を人間の確認なしにそのまま提示する設計は採用しない。

実際に、MVPモックアップ検討時に「LPで会社ドメインを入力すると即座にレポートを生成する」という
セルフサーブ導線が一時的に検討されたが、即時性を担保しようとすると人間レビューを経ずに配信するか、
レビュー待ちで結局即時に見せられないかの二択になり、本原則と両立しないため却下した
（`docs/mockups_v2/CHANGELOG.md`参照）。この判断はPhase1以降も踏襲する。

## 役割分担表

| 工程 | AIの役割 | 人間の役割 |
|---|---|---|
| 会社解析 | データ収集・構造化 | 明らかな誤認識（同名会社との混同等）のチェック |
| 業種推測・関連度判定 | 推定・スコアリング | 確信度が低いケースの最終判断 |
| Opportunity/Action生成 | 文章ドラフト生成 | 事実確認、論理の飛躍がないかの確認 |
| 営業メール生成 | 文面ドラフト生成 | トーン調整、失礼・的外れな表現の除去 |
| 送信判断 | — | **最終承認・送信ボタンは常に人間が押す** |
| フォローアップ | 返信ドラフト生成（将来） | 商談化判断、個別対応 |

創造的な編集（トーン・言い回し）は担当者が調整してよいが、**事実の主張・ターゲティングの妥当性・
機微な情報の扱いはマネージャーが承認する**、という二段階の承認ルールを設ける。

## レビューチェックリスト（送信前必須確認）

1. 会社名・代表者名・業種に誤りがないか
2. 引用しているニュース・法改正情報が最新かつ正確か
3. Opportunityの論理展開が飛躍していないか（薄い根拠で断定していないか）
4. 送信先が [03_lead_generation.md](03_lead_generation.md) の適法な取得経路によるものか
5. 過去に同一企業へ送信済みでないか（重複送信の防止）

## レビューSLA（初期フェーズ）

- 1件あたりのレビュー目標時間: 5〜10分
- レビュー担当者1名が1日にレビューできる件数を上限として、送信数をコントロールする
  （無理に自動化率を上げて質を落とさない）

## 将来的な自動化の進め方

人間レビューの記録（承認/差し戻し/修正内容）を学習データとして蓄積し、
「AIの初稿がどれだけ人間の修正なしで通ったか」を定点観測する。この比率が
十分に高まった工程から段階的に自動化範囲を広げる（[15_roadmap.md](15_roadmap.md)）。
**自動化率の向上はゴールではなく、あくまで品質が伴った場合の結果**として扱う。
