# 07_free_report.md — 無料レポート設計

## 目的

無料レポートは「営業資料」ではなく「営業そのもの」である。読んだ瞬間に
「これは自分（自社）向けだ」と感じてもらうことがすべてのゴールであり、
登録への転換はその結果として起きるものと位置づける。

## 価値の積み上げ設計（発見 → 理解を深める → 実行に移す）

AORの価値提供は、無料版・登録・有料版の3段階で「積み上げ」を作る。

1. **無料版＝発見**: 最も関連性の高いOpportunity1件を提示し、「これは自分（自社）に関係がある」と
   気づいてもらう（`why_now` / `why_company` / `market_change` / `evidence` / `first_action`）
2. **登録＝理解を深める**: 同じOpportunityについて、市場規模・競合状況・実現可能性・リスク・
   優先順位・参考事例まで踏み込んだ追加分析（`extended_analysis`）を提供する。
   **新しいOpportunityを見せるのではなく、同じOpportunityの解像度を上げる**
3. **有料版＝実行に移す**: ロックされていた追加テーマの分析、複数Opportunity間の優先順位付け、
   根拠資料一覧、実行支援、継続モニタリングへと視野を広げる（[08_paid_report.md](08_paid_report.md)）

## 構成案（改訂: 1件深掘り方式）

従来案は「関連度の高い市場変化を1〜3件、浅く並べる」設計だったが、実際の経営者・事業責任者に
「自社向けに考えられた分析だ」と感じてもらうには、**件数より深さ**が効く。無料版は
**最も関連性の高いOpportunity1件に集中**し、その1件を「なぜ今か」「なぜこの会社か」まで
掘り下げて見せる方式に改める。

1. **ヘッダー**: 会社名を明記（「〇〇株式会社様向け レポート」）。誰宛かを一瞬で伝える
2. **サマリー**: 深掘りするOpportunityのタイトルを先出し
3. **深掘りOpportunity（1件）**: 以下の要素をすべて含む、完全な形の分析
   - タイトル
   - なぜ今この機会なのか（`why_now`）: 市場・制度側の変化のタイミング
   - なぜこの会社なのか（`why_company`）: 対象企業固有の事実との結びつき
   - 根拠となる市場変化（`market_change`）: 変化そのものの説明
   - 参照情報（`evidence`）: 上記の根拠となる引用・出典（[04_company_analysis.md](04_company_analysis.md)の
     情報源3階層を組み合わせる。ニュース単独ではなく、一次情報・業界情報と組み合わせて提示する）
   - 最初のアクション案（`first_action`）: 具体的で実行可能な最初の一歩
4. **さらに検討可能なテーマ（ロック）**: 深掘りには至っていないが候補として認識しているテーマを
   **タイトルのみ**提示する（例:「🔒 新規収益モデル候補」「🔒 パートナー戦略候補」）。
   詳細（根拠・アクション）は有料版で初めて分析される
5. **信頼性の明示**: 「このレポートは送信前に人間が内容を確認しています」を目立つ位置に表示する
6. **CTA**: 「詳細レポートを受け取る」ボタン（登録導線）

## 情報量の設計方針

- 無料版は「件数の多さ」ではなく「分析の深さ」で価値を証明する。**1件を深く**掘り下げることに
  生成コストと精度確保のリソースを集中させる
- 複数の情報源（企業の一次情報＋業界情報＋ニュース）を組み合わせて1件のOpportunityを支えることで、
  「ニュースの後追い」ではなく「その会社固有の分析」という体感を作る（[04_company_analysis.md](04_company_analysis.md)）
- 有料版との差分は「量」よりも「深さ・更新頻度・実行支援」であるべき（[08_paid_report.md](08_paid_report.md)）。
  無料版が「1件を深く」なら、有料版は「複数件を同じ深さで、かつ実行支援付きで」提供する、という
  対比を明確にする

## 登録直後の体験（追加分析）

**設計変更**: 「登録直後にロック中のOpportunityを1件、無条件開放する」という旧設計は採用しない。
ロック中テーマはまだ分析すらしていない候補であり、無料版の時点で存在しないデータを取り繕って
見せることになってしまう。代わりに、登録という行動への見返りは、**無料版で提示した同じ
Opportunityの理解を一段深める追加分析**とする。無料版が「これは関係がある」という気づきを
与えるのに対し、登録直後の追加分析は「では、これはどれくらい大きく、実現可能で、リスクは何か」
という**意思決定に近づくための情報**を提供する。

追加分析（`extended_analysis`）の内容:

**名称変更（Phase1最終確定）**: 当初`registration_bonus`という名称で設計したが、
「登録の見返り（ボーナス）」ではなく「同じOpportunityの理解を広げる分析」であることを
名称にも反映するため、`extended_analysis`に変更した。

- **市場規模（market_size）**: このOpportunityが対象とする市場・機会の規模感
- **競合状況（competition）**: 同業他社の動き（定量的な統計比較ではなく、定性的な位置づけ）
- **想定リスク（risks）**: 着手する上での留意点
- **優先順位（priority）**: 他の検討テーマと比べてなぜこれを最優先とすべきか
- **参考となる公開事例（case_examples）**: 同様の取り組みの公開事例（実在する場合は出典を示す。
  存在しない・特定できない場合は「個社名までは特定していない」等と正直に示し、無理に作らない）
- **分析品質の説明（confidence_note）**: どの情報源を組み合わせたか・情報が更新される可能性・
  AI生成後に人間が確認していることを簡潔に説明する。これは**免責文言ではなく、分析の質を
  裏付ける説明**として位置づける（[06_human_review.md](06_human_review.md)の原則を、
  ここでも可視化する）

## 有料版へのブリッジ設計

無料版・登録特典を通じて「1件のOpportunityを深く理解する」体験を提供した上で、有料版では
**視野を広げる**方向に価値を積み上げる。ロック中テーマ（タイトルのみ）の実際の深掘り分析、
複数Opportunity間の優先順位付け、実行支援は[08_paid_report.md](08_paid_report.md)を参照。

推奨アクションについては、無料版で見せる1件は**完全に具体的な実行可能アクションを見せきる**。
中途半端な「方向性のみ」の情報を複数件並べるより、1件を完全に見せきる方が
「これは本気で自社を分析している」という信頼を作りやすい。

## 信頼性の明示（Human in the Loop表示）

レポート画面には、「このレポートは送信前に人間が内容を確認しています」という一文を、
ヘッダーまたはフッターの目立つ位置に必ず表示する。この表示はサービス説明ページ
（`docs/mockups_v2/01_lp.md`）のFAQだけに置くのではなく、**受信者が最初に接触する
レポート画面そのものに置く**（[06_human_review.md](06_human_review.md)の原則を、受信者が
実際に確認できる形で可視化する）。

併せて、会社概要セクションには「この分析は貴社の公開ページ（例: 会社概要ページ、採用ページ）に加え、
官公庁資料・業界団体レポート・ニュース記事を参照して作成しました」と、参照した情報源の種類を
具体的に示す（[04_company_analysis.md](04_company_analysis.md)の「参照元の開示」、source_type/source_roleを参照）。
抽象的な免責文言より、実際に参照した箇所を示す方が信頼構築の効果が高い。

## CTAの配置

- ページ中間（サマリー直後）と末尾の2箇所に配置し、離脱ポイントを問わず登録機会を作る
- CTA文言は「もっと詳しく見る」ではなく、「〇〇業界の変化を継続的に受け取る」など
  具体的なベネフィットを想起させる文言にする（[10_lp_structure.md](10_lp_structure.md)で検証）

## ブランディング

- レポートページ自体がAORの「営業ツール」であるため、初見の企業担当者が違和感を持たない
  信頼感のあるデザインにする（過度な煽り・誇大表現を避ける、[14_risk.md](14_risk.md)）
- 送信元・作成元（自社名）を明記し、匿名性・不透明感を排除する

## A/Bテスト前提

MVPの段階から、以下の要素は継続的に検証・変更する前提で設計する。

- 件名・冒頭文言のパターン
- 深掘りOpportunityの説明の長さ（要約重視 vs 詳細重視）
- ロック中テーマの提示件数・文言
- CTA文言・配置

検証の優先順位・進め方は [16_validation_plan.md](16_validation_plan.md) を参照。
