# 04_company_analysis.md — 企業解析設計

メールドメインを起点に、どこまでの企業情報を自動取得・推測できるかを整理する。

## ドメインから取得できる情報

| 情報 | 取得方法 | 精度 |
|---|---|---|
| 企業ホームページURL | ドメイン直接アクセス、または検索エンジンAPI経由 | 高 |
| 企業規模の一次推定 | WHOIS登録年、サイトのページ数・技術スタック | 中（あくまで補助） |
| 業種の一次推定 | サイトのメタ情報・使用キーワード | 中 |
| 上場/非上場 | 会社概要ページの記載、証券コード有無 | 高（記載があれば） |

海外事例では、ClearbitのようなエンリッチメントAPIが「メール/ドメインを渡すと100以上の
データポイント（業種・従業員数・所在地・技術スタック等）を数秒で返す」仕組みを提供していた
（2026年時点でHubSpot Breeze Intelligenceへ統合されClearbit単体は終了予定）。
日本国内では同等のAPIが少なく、**自前でのHP解析パイプラインを持つ必要性が高い**。

## 会社概要（コーポレートサイトから抽出）

- 会社名・所在地・設立年・資本金・代表者名
- 事業所一覧（複数拠点かどうか＝規模のシグナル）
- 沿革（M&A・事業転換等、変化のヒントになる）

## 事業内容

- 「事業内容」ページのテキストから主要事業ドメインを抽出
- 業種分類（日本標準産業分類等）へのマッピングを試みる

## 製品・サービス

- 製品/サービスページの一覧化
- BtoB / BtoC / 両方かの判定（営業アプローチの角度を変えるために重要）

## 採用情報

- 採用ページの募集職種・人数から、成長シグナル（増員中の部署）を読み取る
- 「DX推進担当募集」等の記載は、そのまま関連度判定（[05_ai_pipeline.md](05_ai_pipeline.md)）の
  重要な入力になる

## ニュース

- プレスリリース・お知らせページ
- 外部ニュースサイト・業界紙での言及（検索API経由）

## IR情報（上場企業のみ）

- 有価証券報告書・決算短信の要旨
- 中期経営計画に記載された重点領域（変化の兆しを掴む一次情報として価値が高い）

## 補助金・助成金情報

- 中小企業庁・各自治体の補助金採択事業者リストとの突合
- 採択実績があれば「投資意欲が高い企業」というシグナルになる

## 法改正影響

- 対象企業の業種に対して、直近の法改正・ガイドライン変更が及ぼす影響を
  ChangeScoutが持つ市場変化データベース（[13_architecture.md](13_architecture.md)参照）と突合する

## 情報ソースの優先順位（拡張版）

「公開情報のみを利用する」という原則（[14_risk.md](14_risk.md)）は維持したまま、
参照可能な情報源を以下の3階層に拡張する。実際の経営者・事業責任者が「自社固有の分析だ」と
感じられる品質は、単一の情報源だけでは作れない。企業の内部事情（一次情報）・業界全体の
潮流（業界情報）・世の中の出来事（ニュース）を**組み合わせる**ことで初めて実現できる。

### 1. 一次情報（最優先）

- 企業公式サイト（会社概要・事業内容・採用ページ等）
- IR資料・決算短信
- 有価証券報告書
- 官公庁資料（府省庁の公表資料、補助金公募要領、法令・ガイドライン）
- 公的統計（経済産業省の統計調査等）

### 2. 業界情報

- 業界団体の発表・プレスリリース
- 業界団体レポート
- 業界動向資料
- 技術ロードマップ

### 3. 大手ニュース・専門メディア

- 大手新聞社
- 経済メディア
- 業界専門ニュース
- 技術系ニュース

## 情報源の利用条件

1. **出典元を必ず表示する**: どの階層のどの情報源に基づく主張かを、レポート上で常に明示する
2. **推測と事実を区別する**: 出典から直接読み取れる事実（例: 補助金の対象経費区分）と、
   AIによる推測（例: 「投資意欲が高いと考えられる」）を、文章の書き分けで区別する
3. **ニュース記事のみを根拠にしない**: 大手ニュース・専門メディアの記事は「世の中で今起きていること」
   の裏付けとしては有効だが、それ単独では「なぜこの会社に関係するか」を語れない。
   必ず一次情報（企業自身の情報）または業界情報と組み合わせて使う
4. **有料記事本文の無断利用はしない**: 見出し・要約・公開されている範囲の情報のみを参照し、
   有料会員限定の本文を転載・要約に使わない

## データソースの優先順位と注意点（取得手段）

1. **企業自身が公開している一次情報**（コーポレートサイト、IR、プレスリリース）を最優先とする
2. 第三者データベース（帝国データバンク・東京商工リサーチ等）は補完的に利用する。
   COSMOSNET API（帝国データバンク）は個別見積制であり、初期フェーズでのコスト負担は大きい。
   G-Search経由の従量課金（企業情報1社あたり1,600〜2,000円）はスモールスタートに向くが、
   大量送付には単価が高い
3. スクレイピングによる取得は、対象サイトの利用規約・著作権に抵触しない範囲に限定する
   （[14_risk.md](14_risk.md)）

## 参照元の開示（信頼性設計）

企業解析パイプラインは、収集した情報のうち**何を参照したか**を構造化データとして保持し、
レポート画面上で開示できるようにする。参照元は「①会社解析」の対象である自社ページに限らず、
「③市場変化抽出」（[05_ai_pipeline.md](05_ai_pipeline.md)）で使う官公庁・業界団体・ニュース等の
外部情報源も含めて、**この分析の根拠となった情報源すべて**を対象とする。

### source_pages のデータ構造

参照元は2つの軸で分類し、「何を根拠にした分析か」が画面上で一目で分かるようにする。

**source_type**（情報源の種別）

| 値 | 意味 |
|---|---|
| `company` | 企業公式サイト・IR資料等、対象企業自身が発信する情報 |
| `government` | 官公庁資料・補助金公募要領・法令・公的統計 |
| `industry_association` | 業界団体の発表・レポート |
| `statistics` | 公的統計（政府統計等） |
| `news` | 大手新聞社・経済メディア・業界専門ニュース |
| `technology` | 技術ロードマップ・技術系ニュース |

**source_role**（分析における役割）

| 値 | 意味 |
|---|---|
| `company_fact` | 対象企業自身に関する事実（採用状況、事業内容等） |
| `market_change` | Opportunityの根拠となる市場変化そのもの（法改正・補助金等） |
| `industry_trend` | 業界全体の傾向・潮流 |
| `evidence` | 上記を補強する追加的な裏付け情報 |

「公開情報のみを使用しています」という抽象的な説明よりも、「貴社の採用ページ」「中小企業庁の
公募要領」「業界団体のレポート」のように種別ごとに具体的に示す方が、受信者にとって検証可能で
信頼できる（`company`種別についてはミラー効果、それ以外は一次情報・業界情報の裏付けとしての信頼性）。
この参照元情報は[07_free_report.md](07_free_report.md)の「信頼性の明示」で使用する。
