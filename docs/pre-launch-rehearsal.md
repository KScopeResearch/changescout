# 運用前リハーサル（Task23）

利用者・運営者の視点で、AORシステムを最初から最後まで実際に操作して総点検した記録。
新機能追加ではなく、既存実装の動作確認・UI/UX総点検が目的。実LLM/実検索providerは
未使用（mock providerのまま）、Node.js標準の`http.server`（website/aor、port 8123）と
`website/aor-admin/server.js`（port 4600）を実際に起動し、Claude Browserで操作した。

## 確認した範囲

- **LP（受信者向け画面、`website/aor/`）**: `report-preview.html`（無料版）・
  `email-capture.html`（登録画面）・`paid-preview.html`（有料版）を、デスクトップ
  （1280px）・タブレット（768px）・モバイル（375px）の3サイズで確認。3社分のサンプル
  データ（`company-01-manufacturing`/`company-02-construction`/`company-03-service`）で
  クロスチェック
- **メールアドレス回収フロー**: 正常系・異常系（不正形式・空欄・日本語・292文字の
  長い文字列）の入力テスト、送信データ・`localStorage`/`sessionStorage`の確認
- **Review Dashboard（`website/aor-admin/`）**: 一覧・詳細・コメント追加・修正指示追加・
  承認・却下・差し戻し・history・SSE自動更新を実操作で確認（2つのブラウザタブを開き、
  片方の操作がもう片方へSSEでリアルタイム反映されることも確認）
- **Jobs Dashboard**: ジョブ追加（generate-report/quality-check）・retry・失敗表示・
  実行時間表示・history・SSE自動更新を実操作で確認
- **Console/Network**: 上記すべての操作を通じて、Console Error・Console Warning・
  Network Errorが（意図的に発生させたエラーケースを除き）0件であることを確認

## 主な確認結果

### LP（3画面 × 3サイズ、計9パターン）

- Console Error/Warning: **0件**（正常系のURL・正常なデータでのアクセス時）
- 横方向のレイアウト崩れ（`scrollWidth > clientWidth`）: **モバイル375px幅を含め検出されず**
- 3社分のサンプルデータいずれでも表示崩れ・console error無し
- 画像アセットは使用していない（テキスト中心のレポートのため、画像読み込み起因の
  問題はそもそも発生しえない設計）

### メールアドレス回収フロー

- **送信データ: 存在しない**。`email-capture.html`のフォーム送信は`event.preventDefault()`で
  ブラウザの既定送信をキャンセルし、`fetch`等によるネットワーク送信を一切行わない
  （Phase1の静的モックとして意図的にそう設計されている。`assets/js/email-capture.js`参照）
- **`localStorage`/`sessionStorage`: 送信前後を通じて空のまま**（実際に送信前後で
  `Object.keys(localStorage)`等を確認し、空配列であることを確認済み）
- バリデーション動作:
  - 空欄 → ブラウザ標準の必須入力エラー（「このフィールドを入力してください。」）で
    送信をブロック
  - 不正形式（`invalid-email-no-at-sign`） → 「メールアドレスを正しい形式で
    入力してください。」を表示
  - 日本語文字列 → 同上のエラーで正しく弾かれる
  - 292文字の長いメールアドレス（形式は正しい） → HTML5の`type="email"`検証は
    長さを制限しないため通過する（`maxlength`属性が無い。実害は無いが将来バックエンドを
    追加する際は要検討。「UX改善一覧」参照）
  - 正常な形式 → 成功画面へ遷移し、入力したメールアドレスがそのまま確認文言に表示され、
    「本モックでは実際のメール送信は行われません」という文言で透明性を確保している

### 無料版・有料版

- 無料版: Opportunity 1件をフル表示、残り2件をロック表示（🔒）して有料版へ誘導する構成。
  CTA（「追加分析を見る（無料）」）は`<main>`内と`<footer>`後の2箇所に存在
- 有料版: 意思決定サマリー・追加Opportunity・優先順位マトリクス（2軸4象限）・
  90日ロードマップ・実行支援メニュー・継続監視テーマ・有料プラン申込みまで、
  スキーマの主要フィールドが漏れなく描画されることを確認。モバイル幅でも
  優先順位マトリクスを含めレイアウト崩れなし

### Review Dashboard

- 承認・却下・差し戻し・コメント追加・修正指示追加を実際に実行し、いずれも
  `review.json`のstatus・history・publishable判定（`isPublishable()`)に正しく反映されることを確認
- 「最終更新」（Task23で追加したフィールド）がコメント追加のたびに正しく更新されることを確認
- 2タブでのSSE確認: 片方のタブで承認操作を行うと、リロードしていないもう一方のタブの
  一覧が即座に更新されることを確認（`review_status`・`publishable`アイコン・`reviewer`列
  すべて正しく反映）
- 日本語＋絵文字を含むコメントも文字化けせず正しく保存・表示されることを確認
  （後述「見つかった問題」の文字化けは過去タスクの残存テストデータであり、現在の
  入力経路には問題が無いことを実際に確認した上で切り分けている）

### Jobs Dashboard

- `quality-check`・`generate-report`ジョブの追加→実行→completed表示、実行時間列
  （Task23で追加）の表示を確認
- 存在しないslugを指定して`quality-check`を実行し、4回試行後にfailedとなり
  `retry`ボタンが表示されることを確認。`retry`ボタンをクリックして再実行されることも確認
- 2タブでのSSE確認: 片方のタブでのジョブ追加・失敗・retryが、リロードしていない
  もう一方のタブにも即座に反映されることを確認

## 見つかった問題（重要度付き）

重要度は★1〜5（★5が最重要）。**★5のみ、可能なら対応**という方針に従い、
今回対応したものと記録に留めたものを分けて示す。

### ★★★★★ 「承認」から「公開」への導線が実装されていない（Task24で対応済み）

> **追記（Task24）**: この課題は[scripts/generator/publish-report.js](../scripts/generator/publish-report.js)
> の追加により解消した。Review Dashboardの詳細画面から明示的に「公開する」操作を
> 行うことで、承認済みレポートがwebsite/aor/data/へ反映されるようになった。
> 詳細は[scripts/generator/README.md](../scripts/generator/README.md)
> 「レポートの公開（Task24で追加）」を参照。以下は発見時（Task23）の記録として残す。

Review Dashboardで`review.status = "approved"`にし`isPublishable()`が`true`になっても、
そのレポートが実際に`website/aor/`（受信者向けLP）で閲覧可能になる仕組みが存在しない。

- `scripts/generator/output/<slug>/report.json`（AIパイプラインの生成物、
  `schema_version: "2.4"`）と、`website/aor/data/<slug>.json`
  （LPが実際に読み込むファイル、同じく`schema_version: "2.4"`）は**スキーマ構造が
  完全に一致している**にもかかわらず、両者を繋ぐコード（コピー・デプロイ・
  シンボリックリンク等、いかなる方法でも）がリポジトリ全体を検索しても存在しない
  （`grep -rl "website/aor/data" scripts/ website/aor-admin/`で0件）
- 4種類のjob type（`generate-report`/`quality-check`/`review-sync`/`search-refresh`）の
  いずれも、`website/aor/data/`への書き込みを行わない
- ドキュメント上も、この「公開」ステップをどう行うか（手動コピー？別スクリプト？）が
  一切記載されていない（`website/aor/`にはREADME.md自体が存在しない）

**影響**: 現状のシステムは「AI生成→品質評価→人間レビュー→承認」までは完全に機能するが、
承認されたレポートを実際の受信者に届ける最後の一歩（公開・配信）が欠落しており、
プロダクトとしての価値提供ループが閉じていない。

**対応しなかった理由**: これは新機能の追加（公開の設計・実装）に該当し、本タスクの
方針「新機能を追加することが目的ではない」に反するため、また「コピーで良いのか、
専用のjob typeを追加すべきか、ファイル配置以外の方法（DB化等）を検討すべきか」という
設計判断が必要なため、今回は記録に留めた。**次タスクでの最優先課題として推奨する**。

### ★★★★ エラーメッセージが実際の原因と異なる場合がある（記録のみ、未対応）

`report-preview.html`/`email-capture.html`/`paid-preview.html`は、データ取得
（`fetch('data/<slug>.json')`）が失敗すると、原因に関わらず常に同じ固定文言
「ブラウザのセキュリティ制限により、file://で直接開いた場合はデータの読み込みが
ブロックされることがあります。簡易サーバーを起動してからアクセスしてください」を表示する。

実際に`?company=does-not-exist`（存在しないslug）でアクセスして確認したところ、
実際の原因はHTTP 404（`data/does-not-exist.json`が存在しない）であるにも関わらず、
file://プロトコルの問題であるかのような、原因の異なる案内が表示された。

**影響**: 通常の利用（システムが生成した正しいリンク経由）では発生しないが、
レポートデータが削除された後の古いメール内リンクへのアクセスや、URLの打ち間違い等で
実際の顧客がこの画面を見る可能性があり、技術的すぎる・的外れな案内は
プロフェッショナルな印象を損ないうる。

**対応しなかった理由**: `website/aor`のUI・仕様は変更しないという本タスクの厳守事項に
従い、記録に留めた。修正する場合はHTTPステータスコードに応じたメッセージ分岐が必要。

### ★★ 無料版レポートにCTAブロックが2箇所存在する（記録のみ、意図的な可能性）

`report-preview.html`は「追加分析を見る（無料）」ボタンを`<main>`内（本文の直後）と
`<footer>`の後（ページ最下部）の2箇所に配置している。ページを最後までスクロールした
読者に再度CTAを提示する意図的な設計の可能性が高く、明確な不具合ではないため
記録のみとした。

### ★ メールアドレス入力に文字数上限が無い（記録のみ、実害なし）

`email-capture.html`の`<input type="email">`に`maxlength`属性が無く、
形式さえ正しければ非常に長い文字列（292文字で確認）も入力・送信可能。
ただし前述の通り実際にはどこにも送信・保存されないため、現時点で実害は無い。
将来バックエンドと連携する際は追加を検討する。

### 参考: 文字化けした古いテストデータ（バグではないことを確認済み）

`scripts/generator/output/example.com/review.json`のcomments配列に、過去タスク
（Task18〜22のいずれか）で追加されたと見られる文字化けしたコメント
（"CSRF"に続いて不正なバイト列）が残っている。本タスクで実際に日本語＋絵文字を含む
新しいコメントを同じUI経由で追加し、正しく保存・表示されることを確認したため、
**現在のコメント投稿経路にエンコーディングの問題は無い**と判断した（過去の別手段
（curl等での直接API呼び出し）によるテストデータの残存と推測される）。データの
実害は無いため、`review.json`のデータ内容変更は行わないという方針に従い、
そのまま残してある。
