# 05_admin_review.md — Human Review画面（社内オペレーション）

対応する設計書: [06_human_review.md](../strategy_v2/06_human_review.md) / [05_ai_pipeline.md](../strategy_v2/05_ai_pipeline.md) / [12_operations.md](../strategy_v2/12_operations.md) / [03_lead_generation.md](../strategy_v2/03_lead_generation.md)

## 位置づけ

顧客（エンドターゲット企業）には一切見えない、**社内向けの運用ツール**。
AIが生成したドラフトを人間が確認・修正し、送信可否を判断するための画面であり、
AOR全体の品質担保の要（[01_concept.md](../strategy_v2/01_concept.md)の
「AIでドラフトを作り、人間が価値を高める」を具体化する画面）。

## 目的

1件あたり5〜10分のレビューSLA（[06_human_review.md](../strategy_v2/06_human_review.md)）の中で、
誤情報・的外れな提案・法的リスクのある送信を確実に防ぎつつ、レビュー担当者の負荷を最小化すること。

## 誰が使うか

AOR運営担当者（初期フェーズは創業者本人1名、[12_operations.md](../strategy_v2/12_operations.md)）。

## ユーザー心理

「早く・安全に処理したい」「見落としたくない」という緊張感の中で、大量のドラフトを
さばく必要がある。チェックリストによる型化と、判断に迷うケースの視認性が重要になる。

## CTA

- 「承認して送信」
- 「差し戻し（要修正）」→ 修正後に再度レビューキューへ
- 「破棄」（送信しない。理由の記録が必須）

## 画面構成

### 一覧画面（レビューキュー）

- 対象会社名、生成日時、総合信頼度スコア、ステータス（未レビュー/差し戻し中/承認済み/送信済み）の一覧
- 信頼度スコアが低い順、または生成日時順にソート可能
- 信頼度が閾値未満の案件には警告バッジを表示し、優先的にレビュー対象として目立たせる
  （[05_ai_pipeline.md](../strategy_v2/05_ai_pipeline.md)の信頼度スコア設計と連動）

### 詳細画面（既定表示）

レビュー担当者が日常的に見るのは以下2点のみとする。情報過多による見落としを防ぐため、
パイプライン全ステップの出力は既定では折りたたんでおく。

1. **レビューチェックリスト**（[06_human_review.md](../strategy_v2/06_human_review.md)の5項目をそのままチェックボックス化）
   - 会社名・代表者名・業種に誤りがないか
   - 引用しているニュース・法改正情報が最新かつ正確か
   - Opportunityの論理展開が飛躍していないか
   - 送信先が適法な取得経路によるものか
   - 過去に同一企業へ送信済みでないか
2. **最終ドラフト（編集エリア）**
   - レポート本文・営業メール文面をその場でインライン編集
   - 編集前後の差分が分かるようにする（何を修正したかの記録目的）

### 詳細画面（展開表示、異常時のみ）

信頼度スコアが低い、またはチェックリストで問題を検知した場合にのみ展開する。

3. **パイプライン出力の並列表示**
   - ①会社解析 → ②業種推測 → ③市場変化抽出 → ④関連度判定 → ⑤Opportunity生成 →
     ⑥Action生成 → ⑦営業メール生成、の各ステップの出力を上から順に表示
   - 各ステップに信頼度スコアをバッジ表示し、低スコアのステップを強調する
   - この内部信頼度スコアは受信者向け画面（[02_report_preview.md](02_report_preview.md)）には
     表示しない、社内専用の数値である（[05_ai_pipeline.md](../strategy_v2/05_ai_pipeline.md)）
4. **送信先情報**
   - 送信先アドレス、取得経路（[03_lead_generation.md](../strategy_v2/03_lead_generation.md)の
     どの経路に該当するか）、オプトイン記録の有無
5. **承認履歴**
   - 誰が・いつ・どのステータスに変更したか、修正内容のログ

## 必要データ

- パイプライン全出力（各ステップの生成結果と信頼度スコア）
- 送信先の取得経路メタデータ（適法性確認用）
- 過去の送信履歴（重複送信チェック用）

## 今はダミーで良い部分

- 信頼度スコアの自動計算ロジック（初期はレビュー担当者が目視で置き換えてもよく、
  UI上のスコア表示枠だけ先に用意する）
- 承認履歴の集計・分析ダッシュボード（Phase 2以降、[15_roadmap.md](../strategy_v2/15_roadmap.md)）

## Phase4以降（現ロードマップのPhase3より先）

- 複数レビュアーによる合議制承認フロー
- 差し戻し理由をAIが学習し、次回ドラフトの精度を自動改善する仕組み
